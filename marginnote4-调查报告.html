① 一句话结论

MN4 的灵魂不是任何一个具体功能，而是一条架构决策：「卡片轴心」——一段摘录只有一个数据本体（带稳定 ID），文档高亮、脑图节点、闪卡都只是这同一个对象的三种渲染。 你的插件已经用 ^ex-xxxx 块 ID + canvas→md 单向同步走到了这条路上的一半；剩下真正值得抄的是 标题链接（旧知识自动浮现）、摘录自动归位到目录上下文、和 Recall 式主动回忆视图。而 MN4 最该绕开的坑恰恰是它的三大重灾区：iCloud 同步、大体量性能、私有格式锁定——这三样 Obsidian 的 markdown-native 架构天然免疫，是你最大的后发优势。
最值得吸取
卡片轴心 + 稳定 ID
一次摘录三处生效（高亮/节点/闪卡），全靠一个 ID 串起来。你已有雏形（^ex- 块 ID），方向正确。
最值得吸取
旧知识自动浮现
新文档里读到旧概念，过去的卡片自动点亮——不搜索、不手动链接。这是 MN4 官网四大卖点之二。
最该绕开的坑
同步是老大难
2026 年 2 月论坛还有人发帖「syncing is still terrible」。手写多的学习集一次同步 4 小时。
最该绕开的坑
私有格式锁定
笔记数据存在 app 本地私有库，不落在 iCloud 文件夹。官方 FAQ 自己都承认「native format is our own」。

② MN4 功能全景What it actually does

MN4 定位是「深度阅读工具」：阅读 → 摘录 → 组织 → 复忆一条龙。官方把它拆成四大模块，外加 2026 年新官网主推的六个场景剧本（PhD 文献综述 / USMLE / 法学院 / 语言学习 / Zettelkasten 等）。按你的插件视角，真正相关的功能分布如下：

📖 阅读与摘录
  • PDF / EPUB / 网页 / 视频音频，统一进「学习集」
  • 极速 OCR：公式、表格、手写识别
  • 留白 Extended Note 4.0+：长按任意位置长出写作空间（嵌入/页边/折叠三态）
  • 书籍重编：折叠章节、跨书拼接页面
  • 双文对照：两文档同步滚动
  • 手写图层：墨迹随开随关，一本书多轮精读
🗺 组织与连接
  • 卡片轴心：摘录 = 高亮 = 脑图节点 = 闪卡
  • 10 种脑图样式（树/鱼骨/时间线/概念图/矩阵…）
  • 大纲视图：同一数据换一种渲染
  • 标题链接 Title Link 4.0：旧笔记在新文档自动浮现
  • 条件脑图：按颜色/标签等 10 种属性自动生成结构
  • 多层脑图图层 + 回链（页码/脑图位置/手写时间戳）
🔁 复习与记忆
  • FSRS 间隔重复（open-spaced-repetition 开源算法，Anki 23.10+ 同款默认）
  • 沉浸模式 4.4：读/写/忆三态；Recall 态摘录高斯模糊，主动回忆才点开
  • 文档回忆：隐藏高亮和墨迹，重读变重记
  • 卡片盒看板：按颜色/标签多级分组的 Zettelkasten 式卡片墙
  • Apple Intelligence 端侧提示（iOS 26+，断网自动兜底）
🤖 AI 与分享
  • AI 拆书 / 翻译 / 问答 / 卡片生成 4.2，官方立场「可接受可拒绝，AI 起草你决定」
  • AI OCR 模板、公式/图表一键提取为卡片
  • Markdown / OPML / Anki 导出（原生格式仍是私有的）
  • iCloud 同步（唯一选项）+ WebDAV/百度网盘/Google Drive 备份 4.3
  • URL Scheme 深链跳转 + 端到端加密学习集分享

③ 值得吸取的 8 个设计Steal these

每一条都标注了「对照你的插件」现状：已有 = 已落地或方向一致；可落地 = 技术上在你的插件里能直接做；远期 = 值得记下但不急。

1
卡片轴心 + 稳定块 ID
已有雏形
MN4 做法
摘录只有一个本体，高亮/节点/闪卡是三种渲染。删除、编辑、链接都作用在本体上。
你的现状
^ex-xxxx 已经是卡片本体 ID，canvas 是主本、摘录 md 是同步镜像——与 MN4 同构，且你选的单向同步比 MN 更干净（MN 自己都没做完双向）。
补强建议
把 exId 的生成从 Math.random() 换成内容哈希（对选区文本+页码+偏移取短哈希），同一选区重复摘录时能识别为「已有卡片」而不是再造一张——这是卡片轴心发挥威力的前提。
2
标题链接：旧知识自动浮现
可落地
MN4 做法
卡片标题成为关键词；读新文档时，命中旧卡片的词自动在页面上点亮——「不点击、不搜索、不手动建链」。
落地建议
Obsidian 有全库搜索 API，这是 MN 做不到的（它只有自己库内数据）。在你创建摘录卡时，顺手用选区文本做一次 vault 检索，卡片底部加一行 🔗 库内已有 3 条相关笔记，点击展开链接列表。零 AI 依赖、纯本地、成本极低。
3
摘录精确归位到目录上下文
可落地
MN4 做法
MN3→MN4 最大的口碑提升点之一：摘录能精确插入到正确的目录节点下（MN3 时代两个节点挨得近就会归错，用户天天手动拖回）。官方论坛老用户明确说「这次升级值回票价」主要就指这个。
教训
摘录默认落在哪，是这类产品的第一 UX 决策，比任何炫功能都重要。
落地建议
摘录 md 的同步条目里，把 PDF 当前页对应的目录/章节路径（PDF++ 能拿到 outline）写成条目头，如 ## 3.2 注意力机制的瓶颈，让摘录文档天然按文档结构聚簇，而不是时间序平铺。
4
沉浸 Recall：高斯模糊 → 主动回忆
远期
MN4 做法
4.4 的招牌：UI 全部折走，只留一个胶囊；Recall 态下摘录自动高斯模糊，用户主动回忆后才点击揭示。把「复习」嵌进了阅读界面本身，而不是跳去另一个 app。
落地建议
CSS filter: blur() 就能做：给摘录卡片加「回忆模式」开关，正文模糊、来源链接保持可见，点击揭示并记录「想起来了吗」。不用做完整 FSRS 调度（那是 obsidian-spaced-repetition 的地盘），做成「把今天的 canvas 卡片模糊重过一遍」就够独特。
5
一份数据，多种视图
远期
MN4 做法
同一批卡片可渲染成脑图、大纲、卡片墙（按颜色/标签分组的看板）。用户不需要「导出到大纲工具」，切个视图就行。
落地建议
你的摘录 md 本来就是结构化文本——加一个「大纲视图」命令，把摘录文档按章节/颜色渲染成 Obsidian outline 即可，成本几乎为零。卡片墙可借助 Dataview 查询文档，不必自己做 UI。
6
颜色即语义（知识编码）
可落地
MN4 做法
官方把自定义工具栏描述为「让批注成为知识编码过程」：颜色、标签、cloze 各代表一类概念；条件脑图、卡片墙分组都建立在这套语义色之上。CSDN 上的科研工作流文也在用同一套（黄=核心观点/绿=方法/蓝=存疑…）。
落地建议
摘录卡片把 PDF++ 的高亮颜色带进 md（frontmatter 或 callout 颜色），并允许用户在设置里自定义「颜色 → 含义」映射表。这样摘录文档可以直接被 Dataview 按「所有蓝色=存疑处」查询。

AI 只做起草，用户拍板
远期

你的定位应该更克制：pdf++ 插件的一切 AI 能力（比如「为摘录生成一句话标题」「相关笔记聚类」）都走「建议暂存区」，用户点了才写入 md。这与 MN 的立场一致，也符合 Obsidian 社区对隐私的偏好。

④ MN4 的短板与教训What to avoid

以下每条都有真实用户证据（官方论坛 / App Store 评论 / 中文社区），不是猜测：

iCloud 同步不可靠严重 · 最大槽点
多设备同步慢、卡住、需反复手动触发；手写内容多的学习集一次上传可达 4 小时；2026 年 2 月论坛仍有「Syncing is still terrible between Mac and iPad」的帖子，且有老用户因此转投 LiquidText。iCloud 还是唯一云选项。 证据：forum.marginnote.com/t/10373（2025-07 至 2026-02 持续更新）；bbs.marginnote.com.cn/t/topic/57092「同步还是老大难，有时候需要手动同步很多次才能同步上」
大体量学习集性能崩严重
大教材 + 图片多的学习集在 M1 8GB MacBook Air 上「太慢、 glitchy、丢过工作」；2019 年 Intel Mac 用户称「卡的不行」。数据全部存在 app 私有库里，量大之后没有逃生通道。 证据：App Store 评论 ahclevername（2025-02，★☆☆☆☆ 级吐槽）；bbs 57092 评论区 Intel Mac 反馈
私有格式锁定中等 · 长期风险
iCloud 文件夹只存 PDF 原始文件，笔记数据不存在里面（官方客服原话确认）；官方 FAQ 承认「our native format is our own」，导出只是桥梁。有用户因此立誓「永远不再依赖单一私有批注格式」。 证据：bbs.marginnote.com.cn/t/topic/51521 客服问答；官方 scenarios/reading.html 对比表自述
功能堆砌 + 学习曲线陡中等
老用户评价 MN4「更多的是功能的堆砌」；工具栏的翻译/朗读/研究等按钮无法关闭；4K 显示器下布局失控；学习集只能平铺不能建文件夹；版本号碎片化（「连重度老用户都看得云里雾里」）。App Store 高赞评论也承认「learning curve, but the best once you get the hang of it」。 证据：bbs 51521 / 57092；App Store 评论（4.2.3）
基础 PDF 操作反而缺失轻度 · 但扎心
用户列的恶心清单：不能整页复制/粘贴/移动/删除、导出 PDF 不能选页、没有直线工具、从电脑导入 PDF 步骤繁琐、EPUB 支持弱、Anki 导出是未渲染的 markdown。功能大而全，基本功反而漏风。 证据：spark.mwm.ai 收录的 App Store 中文差评（4.2.3）；bbs 57092
给你的三条「反面教训」转译
① 单向同步不是妥协，是护城河——MN 一直没修好双向同步的冲突问题，你 v1 的 canvas→md 单向主本是对的，别急着做反向。② 性能上限在设计期就定了——MN 的慢源于私有库 + 全量渲染；你的插件要坚持：markdown 文本文件为主体、canvas 监听做 debounce、大画布卡片懒渲染。③ 克制是功能——MN 被「堆砌」反噬；插件的每一个新按钮都要问一句「能不能不做」。

⑥ 对插件的行动清单Next steps

P0
exId 换成内容寻址（选区文本+页码+偏移 的短哈希）
同一选区重复拖拽能识别为已有卡片而非重复创建。这是「卡片轴心」从雏形变成真架构的分水岭，也是后续一切（去重、旧知识浮现、引用计数）的地基。改动极小：只动 exId 生成一处。
P0
canvas modify 监听加 debounce + 摘录 md 原子写
MN 的性能惨案证明「每次编辑全量重写」扛不住量。连续编辑卡片时应合并为一次写盘（建议 800ms debounce），写 md 时先写临时内容再替换，避免大库下的抖动。
P1
摘录文档按目录结构归位（学 MN4 最受好评的改进）
从 PDF++ 拿当前页的 outline 路径，写入摘录条目头，让摘录 md 长成「按章节聚簇」的结构而不是时间流水。同时回填 frontmatter：created 时间戳、高亮颜色、标签。
P1
创建卡片时顺带做一次全库相关笔记检索（标题链接平替）
用选区前若干关键词查 vault，卡片上显示「库内已有 N 条相关」+ 链接。零 AI、纯本地、几十行代码，是 MN4 标题链接在 Obsidian 里的超集版。
P1
颜色语义映射表（设置项）
用户自定义「高亮颜色 → 含义」（如 黄=核心观点 / 蓝=存疑），映射写入摘录 frontmatter，Dataview 即可按语义查询。MN 验证过这是高频刚需。
P2
Recall 回忆视图：canvas 卡片高斯模糊重过
CSS blur + 点击揭示 + 简单记住「想起来了/没想起」。不做完整 FSRS 调度，避免与 obsidian-spaced-repetition 重复造轮子。
P2
摘录 md 大纲视图（命令面板一键渲染）
MN「同一数据多种视图」的低成本版本：把摘录文档按章节渲染成层级大纲。卡片墙交给 Dataview。
明确不建议做的（MN 教训反推）
① 双向同步（md→canvas 回写）——MN 多年未解决，v1 单向即可；② 自研 OCR/手写——MN 的强项但与你的定位无关；③ 内置完整 FSRS 调度器——生态里已有成熟插件，做导出对接即可；④ 任何「存到插件私有存储」的数据——凡是卡片本体信息必须落在 md/canvas 明文里，这是你对 MN 最大的架构优势，别亲手丢掉。
