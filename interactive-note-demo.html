3 · 可行性结论（调研结果）




  

    
问题结论依据 / 备注

    

      canvas 文本卡支持 markdown 链接吗？
      支持
      官方文档：文本卡「You can use Markdown, links, and code blocks the same way as in a note」。
          社区 bug 报告也证实点击 canvas 里的链接能跳转到目标笔记。
    

    

      canvas 阅读模式里链接可点击吗？
      可以
      单击 = 选中卡片，但点在链接文字上时走链接逻辑（同 Live Preview 的 a.internal-link 管道）。
          注意：canvas 有按缩放比例的「渲染断点」，缩得太小节点内容不渲染，链接就不存在。
    

    

      registerObsidianProtocolHandler 存在吗？版本要求？
      存在，很老
      官方 API（Plugin 类方法），changelog 里「There is now an API available to handle URI
          actions using the obsidian:// protocol」出自 0.9.x 时代。manifest 里
          minAppVersion 写 1.0.0 以上即可覆盖几乎所有现役用户。
    

    

      handler 能拿到 URL 参数吗？
      能，且已解码
      handler 收到的是已经解析好的对象，不用自己跑 URLSearchParams。
          obsidian://myaction?file=a.canvas&node=b
           → {file:"a.canvas", node:"b"}。
          坑：写入 node.text 前必须百分号编码（/→%2F、
          空格→%20），未编码的空格会截断 URL。
    

    

      action 名能带点吗？pdf-plus-drag.addNote
      有风险，建议改
      URI 里 obsidian://<action>?... 的 host 段就是 action。
          社区里见到的实例（clickup、advanced-uri、playground）
          都是纯字母数字+连字符。带点没有先例 →
          改成 obsidian://pdf-plus-drag?action=addNote&... 最稳。
    

    

      点 canvas 里的 obsidian:// 链接，会触发插件 handler 吗？
      高度可能，但未经证实 —— 必须在真机验证
      已知：在普通笔记里点 [x](obsidian://open?...) 会走应用内路由
          （不走操作系统），官方 bug 报告里有用户明确写「clicking the same link from within a regular
          Obsidian note works as expected」。
          canvas 用同一套 MarkdownRenderer，理论上同管道；
          但 canvas 对外链有自己一套处理（shell.openExternal），
          没有找到 canvas + obsidian:// 的直接证据。这是本方案唯一的关键不确定点。
    

    

      dataviewjs 在 canvas 节点里能跑吗？
      不能（至少不可靠）
      dataview issue #1655：DQL 代码块后来被部分修好，但
          dataviewjs 的 promise / 内联查询在 canvas 里仍然不工作。
          → 排除「用 dataviewjs 渲染评论」这条路。
    

    

      canvas 节点内容会被 metadataCache 索引吗？
      不会
      Obsidian 硬编码了 "md" === file.extension 判断，
          canvas 文本卡里的 [[链接]]、#标签 都不进索引。
          → 别指望靠搜索/反链找到评论。
    

    

      还有别的可点击 markdown 元素吗？
      有，都更差
      ① [[不存在的文件]] → 点击会新建笔记，插件没法「拦截不存在事件」，
          只能事后监听 vault.on('create') 再删掉 —— 会闪一下空白笔记，体验很差。
          ② ![[]] 嵌入、③ HTML <button>（canvas 会剥离或转义）。
          → 都不如 obsidian:// 链接。
    

  





最终推荐



  

    结论：v0.8.4 可行，但不要裸奔依赖 canvas 的链接路由。用「三层保险」把它变成确定可行：
  

  
// 第 1 层（主）：协议 handler —— 优雅，但如果 canvas 不路由就完全不工作
this.registerObsidianProtocolHandler("pdf-plus-drag", (p) => {
  if (p.action === "addNote") this.openNoteModal(p.file, p.node);
});

// 第 2 层（兜底，必做）：捕获阶段拦截 canvas 内的协议链接点击
// 就算 canvas 把 obsidian:// 当外链丢给系统，我们也能先一步接住
this.registerDomEvent(document, "click", (e) => {
  const a = e.target.closest && e.target.closest('a[href^="obsidian://pdf-plus-drag"]');
  if (!a) return;
  e.preventDefault(); e.stopPropagation();          // 阻止外抛给系统
  const p = new URLSearchParams(a.getAttribute("href").split("?")[1] || "");
  this.openNoteModal(p.get("file"), p.get("node"));
}, true);

// 第 3 层（永远可用）：命令面板 + 右键菜单，不依赖任何链接行为
this.addCommand({ id: "ppd-add-note", name: "为选中卡片添加/编辑评论", callback: ... });
this.registerEvent(
  this.app.workspace.on("file-menu", (menu, file) => { /* canvas 右键 */ })
);

  

    代价与折中：评论不在 canvas 的 node.text 里，所以
    ① 导出/分享 canvas 时评论不会跟着走；② 全局搜索搜不到评论；
    ③ canvas 上看评论要靠插件注入 DOM，节点被回收重渲染时会被冲掉（上面「模拟 canvas 重新渲染」按钮复现的就是这个）。

    建议：把评论的「权威副本」放在 sidecar，canvas 上的显示当作可随时重建的缓存；
    并提供一个「把评论固化进 node.text（callout）」的命令，供需要导出/搜索时手动降级回 v0.8.3 形态。

① 数据怎么存

    
// 插件 data.json
{

  "comments": {
    // key = canvas 路径 + 节点 id，避免不同画布同名冲突
    "摘录.canvas#7f3a1c2d9e8b45a6": {

// 读写（Plugin 自带，无需引第三方库）
const data = (await this.loadData()) || {};
data.comments = data.comments || {};
data.comments[key] = { text, updated: Date.now() };
await this.saveData(data);

    

      key 必须带 canvas 路径：节点 id 只在同一张画布内唯一，
      用户可能有多张画布都从同一个 PDF 拖出摘录。
    

  


  

    
② node.text 怎么写

    
// 生成链接（务必编码）
function makeNoteLink(canvasPath, nodeId) {
  const q = new URLSearchParams({
    action: "addNote",
    file: canvasPath,
    node: nodeId
  }).toString();          // 自动把 / 和空格编成 %2F %20
  return "[💬 添加评论](obsidian://pdf-plus-drag?" + q + ")";
}

// 判断这个节点是不是我们的摘录卡：靠 ^ex-xxxx 块 id
const EX_ID_RE = /\^ex-[0-9a-z]{4,8}/;

// 写入时：正文 + 换行 + 块 id + 空行 + 链接行
// 注意块 id 必须紧跟正文（否则 Obsidian 不认这个 block ref）
node.text = body + "\n^ex-" + id + "\n\n" + makeNoteLink(path, node.id);

    

      坑：链接行和 ^ex-xxxx 之间必须留空行，
      否则 markdown 会把链接并进块 id 那一段，块引用就废了。
    

  


  

    
③ handler 怎么写

    
async onload() {
  await this.loadSettings();

  this.registerObsidianProtocolHandler(
    "pdf-plus-drag",
    async (params) => {
      // params 已经解析好，形如 { action, file, node }
      const { action, file, node } = params || {};
      if (action !== "addNote") return;

      // 白名单校验：协议链接可能来自任何地方
      const f = this.app.vault.getAbstractFileByPath(file || "");
      if (!f || f.extension !== "canvas") {
        new Notice("卡片所在的画布不存在");
        return;
      }
      this.openNoteModal(file, node);
    }
  );
}

    

      坑：协议参数是外部可控输入 —— 一定要校验路径存在、扩展名是 canvas，
      别拿它去拼 vault.adapter 的路径（目录穿越）。
    

  


  

    
④ Modal 怎么弹

    
class PPDNoteModal extends Modal {
  constructor(app, plugin, canvasPath, nodeId) {
    super(app);
    this.plugin = plugin;
    this.key = canvasPath + "#" + nodeId;
  }
  onOpen() {
    const { contentEl } = this;
    contentEl.createEl("h3", { text: "添加评论" });

    const ta = contentEl.createEl("textarea");
    ta.value = (this.plugin.commentOf(this.key) || "");
    ta.style.cssText = "width:100%;min-height:160px";

    new Setting(contentEl).addButton((b) =>
      b.setButtonText("保存").setCta().onClick(async () => {
        await this.plugin.saveComment(this.key, ta.value);
        this.plugin.refreshCanvas();   // 触发第 5 步的 DOM 注入
        this.close();
      })
    );
    ta.focus();
  }
  onClose() { this.contentEl.empty(); }
}

  


  

    
⑤ 评论怎么画到 canvas 上

    
// canvas 只读 node.text，不会渲染 sidecar → 只能注入 DOM
refreshCanvas() {
  const leaves = this.app.workspace.getLeavesOfType("canvas");
  for (const leaf of leaves) {
    const root = leaf.view.containerEl;
    root.querySelectorAll(".canvas-node-content").forEach(...);
    // 找到 nodeId 对应的节点容器，append 评论 div
  }
}

// 关键：canvas 会随时重渲染，必须盯着 DOM 重新注入
const mo = new MutationObserver(() => this.scheduleRefresh());
mo.observe(canvasRoot, { childList: true, subtree: true });
this.register(() => mo.disconnect());

    

      坑：① 节点 id 在 DOM 上表现为 data-node-id，靠它定位；
      ② 缩得太小时 canvas 不渲染节点内容（渲染断点），注入目标不存在；
      ③ 注入前先检查自己的标记 class，避免 Observer 无限递归；
      ④ 卸载插件时必须 disconnect() 并清掉注入的 DOM。
    

  


  

    
⑥ 迁移与兼容

    
// v0.8.3 升级：把已有 callout 里的正文搬进 sidecar
async migrate083to084() {
  const data = (await this.loadData()) || {};
  if (data.version >= 2) return;

  for (const file of this.app.vault.getFiles()) {
    if (file.extension !== "canvas") continue;
    const json = JSON.parse(await this.app.vault.read(file));
    for (const node of json.nodes || []) {
      const parsed = ppdSplitNote(node.text);   // 沿用 v0.8.3 解析器
      if (!parsed.hasNote) continue;
      // 正文 → sidecar，节点只留链接
      data.comments[file.path + "#" + node.id] = { text: parsed.note };
      node.text = ppdJoinNoteLink(parsed.body, node.id, file.path);
    }
    await this.app.vault.modify(file, JSON.stringify(json));
  }
  data.version = 2;
  await this.saveData(data);   // 注意先 migrate 再 saveSettings
}

    

      坑：迁移会改写 .canvas 文件 —— 一定要先提示用户备份，并提供「回滚到 callout」命令。
      另外 saveSettings() 会整体覆写 data.json，
      顺序必须是「先 migrate（读到旧数据）→ 再 saveSettings」，反过来会把评论冲掉。
