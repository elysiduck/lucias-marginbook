# 备注流程核验（0.34.2）

本次增加 `tests/pdf-note-flow-preview.js`，浏览器入口为 `tests/text-block-preview.html?flow`。使用实际插件代码，PDF/Obsidian 文件 API 由内存替身提供，设置写入调用真实的 `saveSettings` 队列；模拟磁盘保存成功后另存一份持久数据，结束时重新读取，避免仅检查输入框而遗漏未落盘内容。

三类输入各执行同一套连续操作：鼠标、`pointerType: touch`、`pointerType: pen`，共 105 项检查。

| 流程 | 核验内容 |
| --- | --- |
| 新建 | 完整按下／松开／点击后编辑器存活并获得焦点；取消手势不创建备注 |
| 中文输入法 | 未确认的候选文字不保存；此时点空白保留编辑器；确认后保存完整文字 |
| Markdown 编辑 | 点击渲染段落编辑；只出现一个输入框；非当前表格正常渲染；原始 Markdown 完整保存 |
| 侧栏往返 | 页内→侧栏、侧栏→另一条、侧栏→页内均先保存；失败停留；重试成功才切换 |
| 自动保存 | 慢速写入期间继续输入；切换等待写入，并补存最新版本 |
| 连续点击 | 快速选择两条备注只打开最终目标，之前内容完整保存 |
| 点击空白 | 成功时保存退出；失败保留草稿、报错及编辑状态；再次点击可重试 |
| 页面重绘 | 替换 PDF 页 DOM 后恢复同一个输入框，保留源码和光标 |
| 滚动／多指取消 | 无 click 的取消手势不会关闭编辑器或产生额外备注 |
| 首次保存失败 | 回滚临时记录但保留输入；重试后只存在一条备注 |
| 重新读取 | 从模拟持久数据重读，确认最终文字一致，无孤立编辑器 |

单元／集成入口 `tests/integration/note-workflow.test.js` 复现原配置写入竞态，并验证写入顺序、失败后的回滚、队列恢复与重试。修复前，第二次写入可以先完成，较早的快照可能覆盖新状态；修复后同一插件实例只有一个 `data.json` 写入者，每次轮到该任务时再生成快照。

另运行既有侧栏／页内交互 74 项和布局 54 项检查，并用浏览器真实鼠标点击及输入验证。测试不连接或修改用户 PDF、备注及画布数据。

边界：touch/pen 为 Chromium 内的合成 PointerEvent，覆盖插件事件路径，但不等同于物理平板、Apple Pencil、iPadOS/WebKit、软键盘与系统手写识别。尚未完成这些真机环境验证。

本次运行结果：105 项串联检查、74 项原有交互检查、54 项布局检查及 8 组 Node 测试全部通过；真实浏览器点击新建、输入后显示“已自动保存”，结束并重新打开后文字一致。详细逐项结果保存于 `tests/note-flow-browser-results.json`。
