# PDF 手写与 Markdown 联动验证（0.35.0）

## 行为

- 手写模式：触控笔书写；手指拖动页面；双指通过宿主 PDF viewer 调整缩放，笔迹保持 PDF 坐标。宿主私有缩放接口不可用时不猜测、不单独缩放笔迹。
- 普通 PointerEvent 的默认 altitudeAngle 不是触控笔证据；明确的 pen/stylus 标识优先，legacy Touch 才使用倾角兜底。大面积接触及笔书写期间的新触控被阻止；先落下的手掌在笔落下后禁用导航，直到接触抬起。
- 局部橡皮默认开启；按屏幕圆形半径和整段移动路径裁切，支持稀疏采样、纵横比例不同的页面、压力插值及笔迹片段独立 ID。直线、矩形被擦后保留为可编辑笔迹片段；文字对象按整体擦除。
- 一次擦除对应一条撤销记录；取消擦除回滚本次更改。更多设置和插件设置页均可切换整笔／局部与擦完回笔。
- 开启手写前走现有 Markdown 编辑器的保存队列；保存失败或仍在输入法组合期间，不盖住编辑器、不丢弃草稿。进入侧栏或页内 Markdown 编辑时退出手写。
- 文本输入不接受手写层的撤销、删除、Escape 和空格抓手快捷键。书写产生的尾随 click 不触发 Markdown 开启或点击空白退出。
- 页面复用前提交已采样的笔迹；清空活动帧，避免已完成笔迹再次绘制成幽灵预览。卸载时移除旧输入层和观察器，重载后重新绑定。

## 自动验证

最终结果：8 组 Node 测试通过；浏览器 32 项手写联动、105 项备注串联、74 项侧栏交互及 54 项布局检查通过。逐项手写报告见 `tests/ink-browser-results.json`，预览截图见 `ink-workflow-0350.png`。

- `npm run build`、`npm run verify`：8 组测试，含几何裁切、撤销重做、压感、跨事件输入、防误触、缩放路由、存储失败、备份恢复与 Markdown 并发保存。
- `tests/text-block-preview.html?ink`：真实 Chromium DOM/Canvas，合成 pen/touch PointerEvent；验证手写、先落掌后落笔、局部／整笔、擦后回笔、撤销重做、取消、手指拖动、PDF 缩放适配、Markdown 保存失败与重试、侧栏自动保存和窄面板布局。可见结果为 `#ink-results`，逐项结果在其 `data-report` 属性。
- `tests/text-block-preview.html?flow`：既有 105 项鼠标／手指／笔的 Markdown 串联流程，覆盖新建、中文 IME、实时预览、页内／侧栏切换、点击空白退出、保存失败保留、快速切换、慢保存期间继续输入及持久数据重读。
- `?sidebar`、`?layout`：既有侧栏交互及原位编辑布局回归。

## 实机边界

本次浏览器测试不连接用户文档，不修改实际 PDF、备注或 Canvas。模拟输入不是物理 Apple Pencil／Surface Pen，不能证明 iPadOS/WKWebView 的掌部识别、笔尖延迟、系统笔按钮和缩放接口在所有设备上完全一致。

真机需重点复查：手掌先落下再写、笔与手指快速交替、双指跨页缩放、软键盘与输入法、长时间连续书写、触控笔橡皮端及应用切后台恢复。更新后需重新加载插件才能替换当前运行实例。
